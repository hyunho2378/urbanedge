# 무인 포토부스 운영 연동 리서치 (결제, POS, 카메라, 프린터, 대시보드)

작성: 2026-10-09. 아래 "확인한 사실"은 해당 날짜에 연 페이지에서 직접 읽은 내용만 적었다. "해석"과 "미확인"은 따로 표시한다. 검색 결과 요약 화면까지만 본 출처는 그렇게 적었다.

## 1. 운영사 인터뷰에서 나온 현재 구조 (2026-10-09 인터뷰 기록)

- 부스 3개가 모두 하나의 프로그램에 연결돼 있다. 카메라 프로그램(좌우 반전, 줌, 색, 필터, 결과 저장 폴더)이 있고, 촬영 뒤 결제 데이터는 웹 "POS 시스템 같은" 사이트로 모여 일별, 월별, 연별 매출과 부스별, 시간대별 금액을 본다.
- 키오스크에 할인 쿠폰 입력란이 있으나 거의 쓰지 않는다.
- 프레임 하나를 추가하려 해도 업체가 프로그램 전체를 새로 짜야 한다고 했다. 화면 디자인은 운영사가 했고 업체는 기능만 연결했다.
- 인쇄 오류나 프로그램 오류 때 환불은 매장 옆 전화번호로 사람이 처리한다.
- 업체와 트러블이 있어 새 업체와의 협의를 꺼린다. 반면 프레임 추가, 필터 변경, 조도, 인테리어 갱신에는 예산을 쓸 의향이 있다. 학생 프로토타입은 "작동 방식을 보여 주는 수준"으로 제안하기로 했다.

### 해석
- 오프라인 키오스크 결제는 "VAN 계약, 단말기(또는 키오스크용 리더) 설치, VAN이 주는 결제 모듈로 앱과 단말기 연동" 순서로 보인다. 웹 결제창(PG)과는 별개다.
- 웹 기반 키오스크 앱이 터미널과 직접 말하려면 PC에 Windows 서비스 같은 로컬 에이전트가 있고, 앱은 그 에이전트에 HTTP, WebSocket, 시리얼로 요청하는 구조가 일반적일 것이다. 이 구조를 명시한 공개 문서는 이번에 찾지 못했다(미확인). VAN사에 연동 규격서를 요청해야 한다.
- 현금 투입기(지폐 인식)는 키움페이 K-220B 같은 카드, 현금 겸용 키오스크 제품 설명에서 확인했으나 연동 방식은 확인하지 못했다.

### 미확인
- 가맹점 등록 절차와 비용, 단말기 인증 비용, 개발 모듈 제공 조건. 출처가 비용을 밝힌 곳은 찾지 못해 적지 않는다.
- 삼성페이 MST 방식 지원 여부는 단말기 모델마다 다르다. 제품 목록 기준 IC/MSR 리더가 삼성페이를 처리한다고 표기한 것만 확인했다.

## 3. POS와 매출 데이터

### 확인한 사실
- 포토키오스크 제조사 유비(PhotoQ)는 기기 구매자에게 "관리용 모바일 및 홈페이지"를 기본 제공한다. 기능은 실시간 매출 현황과 통계, 쿠폰 관리와 배포, 광고 영상, 키오스크 화면 모니터링, 원격 제어다. 커스텀 소프트웨어는 유상이다. https://www.yubi.co.kr/www/kiosk_photo/photo2/produce
- 같은 회사 솔루션 페이지는 통합관리 프로그램이 통합 매출, 기기 관리, 통계와 현황, 가맹 비용 정산을 제공하고, 쿠폰과 포인트를 통합 관리한다고 적었다. 별도 S/W 기술지원 계약을 말한다. https://www.yubi.co.kr/www/kiosk_photo/startupinfo/solution
- 위 인터뷰의 운영사 구조(카메라 프로그램 + 매출 사이트)는 이 제품 구성과 같다.

### 해석
- 매출 대시보드는 "키오스크 로컬 DB에 거래 기록 → 클라우드 API로 전송 → 웹 대시보드" 구조다. 우리 프로토타입은 같은 화면(일, 월, 연, 부스별, 시간대별, 결제수단별)을 메모리 저장소로 구현한다.
- 영수증 프린터(ESC/POS)와 현금영수증은 이번 조사에서 공식 문서를 열지 못했다(미확인). 단말기 제품 설명에 3인치 감열 프린터, 현금영수증 서비스 항목이 있는 것까지 확인했다.

## 4. 카메라

### 확인한 사실
- Canon EDSDK는 EOS 카메라를 호스트 PC에서 제어하고 이미지를 PC 저장장치로 전송하는 C 인터페이스 SDK다. Windows, macOS용이며 신청 후 내려받는다. 캐논 기본 소프트웨어를 대체하지 않는다. https://www.kr.canon/support/sdk/sdkMain , https://m.svc.kr.canon/servicerequest/requestPageF_sdk
- 포토스퀘어 장비 글은 라이브뷰와 최종 촬영 구도 일치, 초점, 노출, 화이트밸런스 고정, 연속 촬영 중 멈춤, 재연결을 점검 항목으로 든다. https://photosquare.io/ko/blog/02-equipment (2026-04-02)
- 오픈소스 photobooth는 Windows에서 digiCamControl, Linux에서 gPhoto2로 DSLR을 제어하고, 설정은 관리자 페이지에서 바꾼다. https://github.com/andreknieriem/photobooth , https://digicamcontrol.com/
- Sparkbooth는 웹캠 또는 Canon, Nikon, Sony 카메라로 동작하는 포토부스 앱으로 QR 공유, 자동 인쇄, 결제 화면 표시 기능을 둔다(영어권 행사용). https://sparkbooth.com/ko/

### 해석
- 인터뷰의 "Retro 방 출력이 어둡다"는 증상은 노출, 화이트밸런스, 조명 설정 문제로 보인다. 카메라 설정(밝기, 대비, 색온도, 반전, 줌)을 운영자가 화면에서 바꾸고 부스별로 저장하는 기능이 필요하다. 프로토타입 OpsPanel의 카메라 영역이 이를 보여 준다.
- 실제 기기는 웹 앱이 아니라 로컬 프로그램이 카메라를 제어한다. 브라우저 getUserMedia(웹캠)로는 DSLR 라이브뷰를 못 받는다.

## 5. 인화 프린터

### 확인한 사실
- DNP DS-RX1HS는 통합 키오스크와 현장 사진용 6인치 염료승화 프린터로 소개되고, 4x6 700장을 한 번에 출력할 수 있다. DS620은 4x6 한 장에 8.4초, 파노라마, 스티커, 절취 용지를 지원한다. https://shop.dnpphoto.eu/c/printers
- 포토스퀘어는 DS-RX1HS 계열 염료승화형 프린터를 쓴다고 밝히며 용지와 리본을 한 세트로 쓴다고 설명한다. https://photosquare.io/ko/blog/02-equipment
- Snap360은 Canon EOS와 DNP DS-RX1HS, DS620, QW410을 앱 안에서 직접 연결한다고 적었다. https://snap360app.com/ko/파트너/

### 미확인
- DNP 프린터의 SDK, 스풀러 연동 문서는 열지 못했다. 운영사가 쓰는 프린터 모델도 모른다.

## 6. 포토부스 소프트웨어 시장과 원격 관리

### 확인한 사실
- 유비(PhotoQ): 기본 소프트웨어 무상 제공, 커스텀 소프트웨어 유상, 원격 관리와 실시간 로그, 원격 제어, 쿠폰 배포를 제공한다.
- 같은 페이지는 DSLR, 미러리스, 스트로브 조명, 다중 프린터, QR 다운로드를 구성 옵션으로 둔다. https://www.yubi.co.kr/www/kiosk_photo/photo2

### 해석
- 프레임 추가가 "프로그램 전체 재작성"이 되는 것은 프레임이 코드에 박혀 있기 때문일 가능성이 높다. 시장 제품은 "자유로운 UI/UX"와 커스텀 개발 옵션을 따로 판다. 우리 프로토타입은 프레임을 데이터(이름, 색, 컷 수, 켜기와 끄기)로 두어 추가를 화면 입력으로 끝낸다. 단, 실제 운영 소프트웨어가 이 구조를 따르는지는 모른다.
- 쿠폰: 한 가지 고정 코드는 매일, 사람마다 바꿀 수 없다는 것이 인터뷰의 지적이었다. 제휴처 일일 코드(날짜 시드), 1회용 코드 묶음은 모두 앱 쪽 규칙으로 구현 가능하다. 실제 키오스크의 쿠폰 입력란이 서버 검증을 하는지는 미확인이다.

## 7. 개인정보와 사진 보관

미확인. 이번 조사에서 사진 보관 기간, QR 다운로드 만료에 관한 법령이나 업체 약관을 직접 열어 확인하지 못했다. 운영사 개인정보 처리방침과 약관을 받아 확인해야 한다. 근거 없는 보관 기간 숫자는 문서에 쓰지 않는다.

## 8. 구조도 (해석)

```
[키오스크 화면 앱] --(HTTP/WebSocket/시리얼, 규격은 VAN 제공)--> [로컬 결제 에이전트] --> [카드 단말기/리더(IC, NFC, MSR)] --> [VAN사] --> [카드사]
        |                                                                        [현금 투입기]
        |--(카메라 SDK: EDSDK, digiCamControl, gphoto2)--> [DSLR/웹캠]
        |--(프린터 드라이버/스풀러)--> [DNP 프린터]
        |--(영수증 프린터)
        └--(거래, 촬영, 인화 이벤트)--> [클라우드 API] --> [DB] --> [운영 대시보드(웹): 매출, 환불, 쿠폰, 프레임, 카메라 설정, 원격 상태]
```

## 9. 우리 프로토타입이 하는 것과 실제 연동에 필요한 것

| 기능 | 프로토타입 | 실제로 필요한 것 |
|---|---|---|
| 카드, 삼성페이, 현금, 쿠폰 결제 | 앱 안에서 가상 처리, 거래가 대시보드에 즉시 기록 | VAN사 선택과 가맹점 계약, 인증 단말기와 리더 설치, VAN 결제 모듈로 연동 |
| 환불 | 대시보드에서 상태 변경 | 카드 취소 승인 요청(원거래 정보), 현금영수증 취소 |
| 카메라 설정 | CSS 필터로 미리보기와 저장 이미지에 반영 | EDSDK 등으로 노출, 화이트밸런스를 카메라에 직접 적용 |
| 인화 | 화면 연출 | 프린터 드라이버와 스풀러, 용지 잔량과 오류 상태 수신 |
| 대시보드 | 메모리 저장소(새로고침 시 초기화) | 키오스크 로컬 DB와 클라우드 API, 인증, 백업 |
| 쿠폰 | 일일 코드, 1회용 코드, 웹 스크래치 쿠폰 체크섬 | 서버 검증과 사용 이력, 영수증 하단 코드 출력 |
| 프레임 추가 | 데이터 입력으로 추가 | 이미지 에셋 배포 경로, 키오스크 동기화 |

## 10. 운영사와 업체에 물어볼 목록

1. 현재 VAN사와 가맹점 번호 구조는 무엇인가? 부스 3개가 같은 가맹점인가, 각각인가?

7. 쿠폰 입력란의 검증 방식(서버 조회인지, 로컬 목록인지).
8. 사진 보관 기간, QR 다운로드 만료, 개인정보 처리방침.
9. 환불 절차와 현재 연락 체계(전화), 장애 알림 방식.
