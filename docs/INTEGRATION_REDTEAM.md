### 해석
- 인터뷰의 "카메라 프로그램 + 매출 사이트" 구조가 넥스온의 "촬영 제어 소프트웨어 + 원격관리 모바일 서비스"와 같은 모양이다. 어반엣지 납품 항목까지 있으므로 현재 업체는 넥스온일 가능성이 높다.
- 포트폴리오 게시일(2026.04)이 개점(2024)과 다르다. 추가 설치나 갱신 게시일 수 있어 설치 시점은 확인되지 않았다.

### 미확인
- 카드 단말기와 지폐인식기의 제조사와 모델, VAN사. 프린터 제조사(넥스온은 "염료승화 방식"만 밝히고 브랜드를 적지 않는다). 카메라 기종.
- 넥스온 프로그램이 매출 데이터를 내보내는지(CSV 등). 공개 문서가 없다.
- 계약 상태(구매 또는 렌탈, 소프트웨어 소유권, 유지보수). 운영사에 물어야 한다.

## 2. 대체 프로그램이 실제로 이어지는 구조

```
키오스크 화면(브라우저, apps/kiosk) ──HTTP/WebSocket──▶ 로컬 에이전트(apps/agent, 127.0.0.1:8790)
                                                         ├─ 카메라: gphoto2 | digiCamControl | Canon EDSDK | 웹캠
                                                         ├─ 프린터: OS 스풀러(lp, Windows 인쇄 큐) + 드라이버 용지 옵션
                                                         ├─ 영수증: ESC/POS (CP949)
                                                         ├─ 카드: VAN사 로컬 모듈(TCP/DLL/서비스)
                                                         └─ 지폐: 시리얼/USB 장치
키오스크 화면 ──HTTPS──▶ 클라우드 API(apps/server) ──▶ 대시보드(apps/kiosk 운영 패널)
```
- 브라우저는 장비를 직접 못 쓰므로 에이전트가 필요하다. 이 에이전트는 키오스크 PC에서 돌고, 허용 목록 origin만 받는다(옵션으로 토큰).
- 결제 승인은 VAN 모듈이 한다. 우리 쪽은 요청을 보내고 승인번호, 카드사, 마스킹 번호, 할부, 단말기 ID를 받아 거래에 기록한다.

### 실패하거나 못 한 것
| 항목 | 결과 |

## 5. 위험
- **카드번호:** 원번호(PAN)는 저장하지 않는다. 마스킹(앞 6자리와 뒤 4자리 이하)과 승인번호만 기록한다. 에이전트는 모의 번호도 응답에서 마스킹한다.
- **VAN 인증:** 단말기와 모듈은 인증된 것만 쓴다. 자체 카드 입력창은 만들지 않는다.
- **망취소:** 승인 요청 후 응답이 없으면 실제로는 승인됐을 수 있다. 실제 어댑터는 타임아웃 시 조회와 취소 절차가 필요하다(뼈대에 경고를 남겼다).
- **개인정보:** 얼굴 사진을 서버에 두면 보관 기간과 삭제 규정이 필요하다. QR 링크는 만료시켜야 한다.
- **오프라인:** 인터넷이 끊겨도 결제와 인쇄는 되어야 한다. 현재 키오스크 스토어는 재전송 큐가 있으나 탭을 닫으면 유실된다. 실제 운영 전에 로컬 DB(SQLite)가 필요하다.
- **로컬 에이전트 노출:** 127.0.0.1에만 바인딩하고 허용 origin만 받는다. 같은 PC의 다른 웹페이지가 호출하지 못하도록 `AGENT_TOKEN`을 쓰는 것을 권한다.
- **키 노출:** 키오스크 번들에 들어간 관리자 키는 누구나 볼 수 있다. 실운영에서는 로그인으로 바꿔야 한다.
