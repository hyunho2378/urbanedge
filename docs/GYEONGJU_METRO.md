# GYEONGJU METRO

URBAN EDGE 포토부스를 활용한 외국인 관광객 경험 디자인 제안

경주포럼 프로젝트 · 팀 내부 공유 및 개발 협의용  |  2026.10.09

“지하철이 없는 경주에, 여행자가 찾아가는 가상의 지하철을 만든다.”

## 01. 기획 개요

어반엣지의 기존 브랜드 컨셉인 ‘경주의 지하철이 되겠다’를 외국인 관광객을 위한 관광 UX로 확장한다. 도시 곳곳의 실제 어반엣지 포토부스에 각각 ‘Station’이라는 정체성을 부여하고, 가상의 노선도·모바일 웹·현장 QR·방문 수집 경험을 연결해 사진 촬영을 경주 탐험의 일부로 전환한다.

| 구분 | 제안 내용 |
| --- | --- |
| 프로젝트명(가칭) | GYEONGJU METRO — Powered by URBAN EDGE |
| 핵심 타깃 | 경주를 처음 방문한 외국인 개별 관광객(FIT) |
| 핵심 가치 | 호기심을 유발하는 랜드마크 + 손쉬운 관광 탐색 + 촬영·수집·공유 |
| 핵심 전환 | 포토부스(시설) → Station(발견의 대상) → Metro Journey(경험) |
| 서비스 성격 | 실제 교통수단이 아닌 가상의 지하철 테마 관광 경험 |

## 02. 문제 인식과 기회

### 외국인 입장에서의 진입 장벽

- 경주 관광지의 위치와 동선을 처음부터 파악해야 하며, 기존 관광 안내는 탐색 동기가 약할 수 있다.

- 포토부스는 우연히 발견하면 이용하지만, 그 자체를 목적으로 방문할 이유가 부족할 수 있다.

- 언어, 정보량, 가입 절차가 길면 여행 중 모바일 이용자가 이탈할 가능성이 있다.

### 제안 가설

“경주에는 지하철이 없는데 역이 있다?”라는 역설적 호기심이 부스 발견·검색을 유도하고, ‘역을 방문해 수집하는 경험’이 다음 장소 방문과 사진 촬영으로 이어질 수 있다. 이는 아직 검증 전의 가설이며, 실제 외국인 사용성 테스트로 확인해야 한다.

## 03. 브랜드 세계관 및 공간 디자인

핵심 메시지는 “Explore Gyeongju, One Station at a Time.” 실제 부스가 위치한 장소를 중심으로 역명·역번호를 붙이고, 현장과 웹에서 동일한 명칭과 색상을 사용한다. 지하철 노선도, 역명판, 출구 표시, 승차권, 도장 등 도시교통의 시각 언어를 활용하되 경주의 문화유산 문양은 절제해 적용한다.

| 요소 | 예시 / 디자인 원칙 |
| --- | --- |
| Station 네이밍 | GY-01 Hwangridan-gil Station 등 번호+영문명+한글 병기 |
| 포토부스 외관 | 역명판, 노선 컬러, EXIT 사인, QR 안내문 |
| 인화 프레임 | Metro Ticket / Visit Date / Station Code 모티프 |
| 안내 문구 | “Imaginary Metro · Travel Experience”를 명시해 실제 교통시설 오인 방지 |

※ 황리단길·대릉원·첨성대·동궁과 월지는 컨셉 설명용 후보 관광지다. 실제 Station은 어반엣지 부스의 설치 위치 및 운영 협의가 확인된 장소로만 확정해야 한다.

## 04. 외국인 관광객 UX 설계

### 목표 사용자 흐름

발견(역 형태의 부스/온라인 게시물) → 호기심(QR/사이트 진입) → 이해(가상 노선도) → 선택(Station 상세) → 방문(길찾기) → 촬영(포토부스) → 수집(QR 체크인) → 공유(완료 카드)

| 단계 | 사용자 질문 | 제품·공간의 응답 |
| --- | --- | --- |
| 발견 | “경주에 지하철역이 있어?” | 차별화된 역 사인, 짧은 영문 슬로건, QR |
| 탐색 | “어떤 역들이 있지?” | 모바일 노선도, 방문 가능한 실제 Station |
| 방문 | “어떻게 가고 뭘 할 수 있지?” | 관광 정보 요약, 부스 위치, 외부 지도 연결 |
| 체험 | “여기서 무엇을 해야 하지?” | 사진 촬영 안내, 현장 체크인 |
| 지속 | “다음엔 어디로 가지?” | 방문 진행률, 다음 역 제안 |
| 공유 | “무엇을 남길 수 있지?” | 디지털 패스/여정 완료 이미지 |

### UX 원칙

- 모바일 우선: 첫 화면의 개념 이해와 첫 행동이 빠르게 이어져야 한다.

- 영어 기본 지원 + 한국어 전환; 일본어·중국어는 후속 확장 검토.

- 복잡한 가입 없이 탐색과 체크인을 시작하도록 설계한다.

- 각 Station의 관광지와 부스 위치를 분리 표기해 현장 혼동을 줄인다.

- 실제 운영시간·운영 여부·거리·도보시간은 확인된 데이터만 제공한다.

## 06. 핵심 기능 및 구현 우선순위

| 등급 | 기능 | 판단 기준 |
| --- | --- | --- |
| MVP / P0 | 노선도 + Station 상세 + 현장 QR 체크인 + Metro Pass | 시연 가능한 핵심 경험 완성 |
| MVP / P1 | 영어/한국어 전환 + 길찾기 + 방문 진행률 | 외국인 이용성과 기본 완결성 확보 |
| 확장 / P2 | 공유 이미지 생성, 다음 역 추천, 방문 인증 강화 | 현장 검증 결과에 따라 개발 |
| 추후 검토 | GPS, 개인화 추천, 회원 계정, DB/관리자 페이지 | 운영 규모가 커질 때 도입 |

### 간단 데이터 구조 예시

stations: station_id, station_code, name_en, name_ko, description_en, description_ko, booth_address, latitude, longitude, image_url, map_url, qr_token, active

visitedStations: [station_id, checked_at] — 초기 시연은 브라우저 Local Storage로 저장 가능. 단, 브라우저 변경·데이터 삭제 시 기록이 유지되지 않고 QR 공유로 부정 체크인이 가능하므로 실서비스 인증 방식은 재설계가 필요하다.

## 07. 개발 담당자용 구현 흐름

- ① 실존 부스 위치와 후보 Station 목록을 확정하고, 명칭/위치/영문 소개를 JSON에 정리한다.

- ② 반응형 Metro Map을 제작하고 역 클릭 시 Station 상세로 연결한다.

- ③ 각 부스에 고유 QR URL을 부여해 /check-in/{station_id} 형태로 연결한다.

- ④ 현장 QR 유입 시 방문 기록을 저장하고, Passport 상태와 방문 수를 갱신한다.

- ⑤ 영어/한국어 문구와 외부 길찾기 연동, 운영 여부 표시를 검수한다.

- ⑥ 실제 외국인에게 QR부터 체크인까지 수행하게 하고 막히는 지점을 수정한다.

기술 스택 예시: React/Next.js + 정적 Station JSON + Local Storage. 이는 빠른 프로토타입을 위한 제안이며, 팀 개발 환경에 따라 변경 가능하다.

## 08. 검증 계획과 성공 지표

컨셉의 참신함만이 아니라 실제 행동 변화가 있는지를 살펴야 한다. 행사 전후로 소수의 외국인 사용자에게 관찰 테스트를 진행하고, 이해도·이탈 지점·촬영 의향을 수집한다.

| 확인할 가설 | 측정 방법 |
| --- | --- |
| ‘가상 지하철’ 컨셉이 호기심을 만든다 | 역 사인 노출 후 관심/QR 스캔 의향 및 이해도 인터뷰 |
| 노선도가 이동을 돕는다 | 원하는 역 찾기 성공 여부, 걸린 시간, 길찾기 클릭 |
| 수집 기능이 추가 방문을 유도한다 | 체크인 완료율, 다음 Station 클릭/방문 의향 |
| 포토부스 촬영으로 연결된다 | 현장 촬영 전환 여부, 촬영 이유 인터뷰 |

## 09. 실행 전 팀에서 결정할 사항

- 실제 참여 가능한 어반엣지 부스 위치와 수량은 몇 곳인가?

- 관광지 이름을 역명으로 쓸 때 정확히 어느 부스를 가리키는지 어떻게 명확히 할 것인가?

- 부스 사인·QR·전용 인화 프레임을 실제로 제작·설치할 수 있는가?

- MVP에서 QR 스캔을 방문으로 인정할지, 사진 촬영 완료와 연동할지?

- 브랜드 로고, 공간 사진, 영문 콘텐츠의 사용·관리 권한은 누가 맡는가?

## 10. 결론 및 팀 제안

이 제안의 경쟁력은 단순한 ‘지하철 테마 부스 꾸미기’가 아니라 공간 브랜딩과 디지털 UX를 연결해 외국인이 경주를 탐험하도록 설계한다는 점이다. 공모전 시연에서는 2~3개의 검증된 후보 Station만으로도 “노선도 확인 → 역 선택 → QR 체크인 → Metro Pass 갱신” 흐름을 실제로 보여주는 것을 우선 추천한다.
