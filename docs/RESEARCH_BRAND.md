# 셀프사진관·교통 브랜드 사이트 조사

조사일: 2026-10-09. 모든 항목은 이 날짜에 실제로 열어 본 페이지에서 확인한 것만 적었다. 열지 못한 페이지는 "미확인"으로 표시했다. 사실과 해석은 분리했다. "관찰"은 페이지에서 본 것이고, "해석"은 우리가 내린 판단이다.

## 0. 조사 범위와 한계

- 연 곳: 포토이즘, 하루필름, 인생네컷(국내·영국), 포토그레이, 모노맨션(운영사 하임 페이지), London Transport Museum.
- 서울교통공사(seoulmetro.co.kr)는 검색 결과의 홈 발췌만 확인했고 하위 페이지는 열지 않았다.
- 인생네컷 영국 사이트의 HOW TO USE 페이지는 `/how-to-use` 주소가 404였다. 내용은 미확인이다. 국내 사이트의 "QR코드 사용방법" 페이지도 주소를 못 찾았다(`/QR` 404). 내용은 미확인이다.
- 모노맨션 소비자용 공식 사이트는 열지 못했다. 운영사 하임 사이트의 브랜드 소개만 확인했다.
- 모노맨션 지점 안내 페이지는 탭 이름(모노맨션 / 비비드뮤지엄 / 포토하임)만 읽혔다. 지도 내용은 읽히지 않았다.
- 이용 순서는 공식 사이트에서 찾지 못한 곳이 많다. 그런 곳은 블로그 글을 근거로 쓰고 블로그라고 밝혔다.
- 스크린샷은 `tmp/rs-*.jpg`로 저장했다(세션 임시 폴더, 커밋 대상 아님).

## 2. 관찰에서 읽히는 공통점 (해석)

- 브랜드 소개를 확인한 사진관 4곳(포토이즘, 하루필름, 인생네컷, 모노맨션) 중 시대나 시간여행 같은 이야기로 브랜드를 푼 곳은 없었다. 브랜드 페이지는 한두 문장 비전(하루필름), 짧은 블록 나열(포토이즘), 캐릭터 서사(인생네컷), 소재와 감각 설명(모노맨션)이었다. 어반엣지가 시간 이동 구조를 쓰면 이 분야에서 겹치는 곳이 없다는 뜻이다. 다만 우리가 본 범위 안에서만 한 말이다.
- 이용 안내는 두 갈래다. 기계 조작 순서(하루필름 블로그)와 방문 전체 질문(포토이즘 FAQ). 이동 수단별 안내는 교통 박물관(LTM)에서만 봤다. 어반엣지는 키오스크가 시뮬레이터로 따로 있으므로 웹 How to는 방문 전체로 가는 쪽이 맞다.
- 선택 장치는 탭, 카드, 목록 중 하나였다. 숫자 점이나 번호 배지만으로 고르게 하는 곳은 없었다.
- 흑백 줄무늬를 쓰는 사진관 사이트는 이번 조사에서 보지 못했다. 교통 쪽은 런던 지하철 원형 표지를 로고 틀로 쓰고 있었다.

## 3. UrbanEdge에 적용할 것

현재 코드 사실도 함께 적는다. `RoomExplorer.jsx`의 `useState('subway')`로 기본 선택이 지하철이다. `zones.js`와 `site.js`에는 `entrance`(입구) 항목이 이미 있다. `public/img`에는 `cr_crosswalk.jpg`, `cr_checker.jpg`, `cr_tape.jpg` 등 횡단보도와 체커 소재가 이미 있다. `site.js`의 승강장 번호는 이미 1 Retro(1968), 2 Karaoke(2008), 3 Subway(2000년대)로 되어 있다.

1. **브랜드 페이지를 새로 만들고 상단 메뉴 이름을 "어반엣지"로 한다.** 메뉴 3개 구조(Rooms / How to / Visit)에 맞춰 맨 앞에 두거나, 로고 클릭으로 간다. 포토이즘, 하루필름, 인생네컷 모두 브랜드 소개를 상단 메뉴에 둔다.
2. **브랜드 페이지는 짧게, 시간 순서대로 쓴다.** 비교 사이트의 브랜드 문구는 1~2문장 블록이었다. 인생네컷만 길었다. 긴 설명을 피하고 승강장 3개를 그대로 구조로 쓴다(아래 3-a).
3. **Rooms 기본 선택을 입구(Entrance)로 한다.** 코드에 입구 구역이 이미 있다. 첫 화면은 입구, 다음 선택이 1호선(Retro)이 된다. 지금처럼 3호선이 기본이면 시간 순서(1968 > 2008 > 2000년대)와 어긋난다.
4. **Rooms는 첫 화면 한 장에 들어가게 한다(스크롤 없이, 모바일과 웹 모두).** 사진은 높이를 `min(화면 높이 - 헤더 - 선택 줄, …)`로 묶는다. 해석이지만 LTM Visit과 카드형 사이트들은 첫 화면에 선택지를 먼저 보여 줬다.
5. **선택 장치를 3-c처럼 명시한다.** 번호 배지와 가운데 점을 없애고, 눌러야 하는 곳이 글자로 보이게 한다.
6. **How to는 "찾아오기부터 사진 받기까지"로 쓴다.** 3-b에 단계 문구를 적었다. 키오스크 조작은 단계 안에서 한 줄만 언급한다.
7. **How to 가는 길 항목은 LTM 방식을 따른다.** 교통수단별로 나누고 "역에서 걸어서 몇 분"을 적는다. 현재 사이트의 위치 정보(주소 6, Poseok-ro 1079beon-gil)만 쓰고, 실제 걸리는 시간은 우리가 직접 확인한 값만 넣는다. 확인 전에는 비워 둔다.
8. **횡단보도 줄무늬를 구분선과 강조 장치로 쓴다(3-d).** 노랑은 줄무늬가 아니라 단일 강조색으로 남긴다.
9. **로고의 노란 원 U 마크는 헤더와 푸터에서 뺀다.** 비교 사이트 로고는 글자 중심이었다(포토이즘, 포토그레이, 하루필름은 글자 로고, 인생네컷은 별 모양과 글자). 어반엣지는 글자만 남긴다. "Metrography" 소제는 글자 로고에서 자른다. 모바일은 글자 크기를 더 줄인다.
10. **푸터는 흰 바탕에 글자만 둔다.** 이미 반영했다. 푸터에 아이콘 로고를 다시 넣지 않는다.

### 3-c. Rooms 선택 장치

- 선택 줄은 글자 탭이다. 탭 이름은 "입구 / 1호선 Retro / 2호선 Karaoke / 3호선 Subway"로 쓴다. 지금의 "1 · Subway Shot" 식 번호 점은 뺀다.
- 선택된 탭은 노랑 채움, 나머지는 윤곽선. 탭 줄 오른쪽 끝에 화살표 버튼(이전, 다음)을 둔다. 사진 위에는 "눌러서 이 방 보기"가 아니라 사진 아래 1줄 안내 "다음: 2호선 Karaoke →"를 둔다.
- 방 상세로 가는 버튼은 "이 방 자세히 / View this room" 글자 버튼 하나다. 인생네컷 영국 사이트의 "View Map"처럼 동사가 보이는 링크를 쓴다.
- 현재 이미지 1처럼 `‹ Retro Shot` `Karaoke Shot ›`가 역 표지 안에 작은 글씨로 있으면 누르는 곳인지 알기 어렵다는 지적이 있었다. 표지는 정보 표시로 두고, 누르는 요소는 탭과 아래 화살표 버튼으로 분리한다. (해석)
- 모바일은 탭 줄이 가로로 넘치지 않도록 4개 글자를 줄여 한 줄에 둔다("입구 / 1호선 / 2호선 / 3호선").

### 3-d. 흑백 횡단보도 줄무늬와 노랑 쓰는 법

- 줄무늬는 폭 24px 정도의 흑백 사선이 아닌 수직 막대로 한다. 횡단보도는 평행 막대다.
- 쓰는 곳은 세 곳으로 한정한다. (1) 섹션 사이 구분선(높이 12~16px 띠). (2) 브랜드 슬로건 뒤 배경 띠. (3) 푸터 위 한 줄.
- 노랑은 줄무늬 안에 섞지 않는다. 대신 한 화면에 노랑은 버튼 하나, 선택된 탭 하나, 작은 강조 하나까지만 둔다. 이미 만든 흰색 푸터, 밝은 섹션과 어울린다.
- 줄무늬 위에는 글자를 직접 얹지 않는다. 슬로건처럼 글자를 얹을 때는 줄무늬 위에 단색 판을 한 겹 둔다.
- 소재는 `public/img/cr_crosswalk.jpg`, `cr_checker.jpg`가 이미 있다. 사진 파일 대신 CSS `repeating-linear-gradient`로 그리면 모바일에서 가볍다. (해석)
- 근거와 한계: 이번 조사에서 줄무늬를 쓰는 사진관 사이트는 못 찾았다. 이 제안은 사이트 조사에서 나온 것이 아니라 입구의 체커보드 바닥과 노란 테이프라는 우리 공간 재료에서 나온 해석이다. 교통 쪽 근거는 LTM의 지하철 원형 표지 로고 하나뿐이다.
